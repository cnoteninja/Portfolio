AD Onboarder

Automate Active Directory user onboarding and offboarding from the help desk — no more clicking through ADUC for every new hire and every departure.

About this demo: AD Onboarder is PowerShell and needs a Windows machine joined to a domain (ActiveDirectory module). The full interactive demo (New-DemoOnboarding.ps1) runs there — it simulates three hires end-to-end and produces a styled HTML report. Below is exactly what it runs on, so you can see the shape of it.

1. The input — demo/demo-hires.csv

FirstName,LastName,EmployeeID,Title,Department,ManagerSam,TemplateSam,OU,Password,Email
Maya,Thompson,2001,Help Desk Technician,IT Support,mbrown,template-helpdesk,,,
Derek,Okafor,2002,Paralegal,Litigation,mbrown,template-paralegal,,,
Sofia,Marsh,2003,Office Manager,Administration,mbrown,template-officemgr,,,

2. Run it

# Preview first — always
.\New-ADUser.ps1 -CsvPath .\demo\demo-hires.csv -WhatIf

# For real
.\New-ADUser.ps1 -CsvPath .\demo\demo-hires.csv

# Or skip the CSV entirely for a single hire
.\New-ADUser.ps1 -Interactive

# Offboard someone (with rehire-safe group backup)
.\Disable-ADUser.ps1 -SamAccountName jsmith -Ticket 'HD-4821'

# Find dormant accounts (default: enabled, 45+ days since logon)
.\Find-StaleADAccounts.ps1

3. What you get

  • Onboarding: users created from the CSV, group memberships copied from a template user in the same role, unique usernames, generated temporary passwords, forced password change at first logon — everything logged.
  • Offboarding: account disabled, group memberships stripped (protected groups kept), group list backed up for rehire, account moved to a Disabled Users OU, ticket reference stamped on the account.
  • Audit: stale-account HTML report — enabled accounts dormant 45+ days, with recommended actions. Dormant accounts are how breaches start.
  • Notifications: optional Slack/Teams webhook ping when a batch finishes.
  • Safety: -WhatIf dry-run on every destructive path, plus a prerequisite checker and a first-run setup wizard.
